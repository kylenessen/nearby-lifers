# Nearby Lifers

Nearby Lifers is a responsive website for finding iNaturalist species that you have not observed yet. Run a search, copy its link, or bookmark it. Opening that link restores the settings and fetches current results. There is no installation step, service worker, local storage, or saved account state.

## Searching and sharing

Use the Username field to search iNaturalist by login or display name. Choose a match with the pointer or arrow keys and Enter, or enter an exact username directly. Links containing multiple comma-separated usernames still work. Their worldwide species lists are combined, and an observation from any listed user makes that species already observed. The life list always includes Research Grade and Needs ID. Casual observations also count by default. Select “Exclude users’ casual observations” to leave them out. All dates and locations count toward the life list. Identifications above species rank cannot establish that a particular species has been observed. Subspecies observations count toward their parent species.

Nearby results use the selected location, months, and life groups. Months apply across all years. The initial search uses the previous, current, and next month. Once a URL is created, those months are explicit and stay fixed when that bookmark is reopened. Nearby casual-only and expected-range filters are separate from the users’ life-list quality setting. “Include already observed species” adds those species to the display and marks them as seen.

The address changes when you run a search. Display filters and print settings update it immediately. Unsaved search edits are labeled, and sharing and printing are disabled until the new search runs. Browser Back and Forward restore previous searches. Each bookmark can be added to a phone’s home screen using the browser’s normal website shortcut feature. Mobile bookmarks open with the search controls collapsed so results are visible immediately. Use Edit search to change them.

All settings live in query parameters. These include `users`, `area`, coordinates or `place`, `radius`, `months`, `groups`, `user_casual`, `hide_casual`, `hide_unexpected`, `show_observed`, `layout`, `paper`, `density`, `columns`, `rows`, `font_size`, `sort`, `grouping`, `print`, `title`, `credits`, and `sheet_limit`. `v=1` identifies the URL format. New display options have defaults, so earlier links continue to work. Polygon vertices use latitude and longitude pairs in `polygon`. Links preserve a deployment subdirectory such as `/nearby-lifers/`. Invalid locations or unsupported URL versions show an error instead of running a different search.

The checklist uses iNaturalist taxonomic ancestry to group species. Taxonomic groups use families such as ducks and geese or herons, with Passeriformes grouped together as perching birds. You can instead group everything by family or order. Missing ancestry falls back to the life group. Sort by common name, scientific name, or reported observation count within groups. Set Group by to None for a single globally sorted list. Photo grids use the same grouping and sort controls. Groups flow through the grid without empty rows or forced page breaks. The default is most frequently recorded first within each group, using the selected area and months. Large, Comfortable, Compact, and Extra compact densities affect screen layouts and printed checklist spacing. For printed photo grids, text size and grid dimensions can be adjusted separately.

## Map selection

Explore mode lets you move the map without changing the selected area. Radius mode sets a center with one tap. Rectangle mode uses two opposite corners and previews the boundary. Polygon mode lets you tap corners, undo points, drag numbered corners, and finish the shape. Existing polygons can be edited. Escape cancels drawing. With the map focused, arrow keys pan and Enter adds a point at the center. Place search accepts an iNaturalist place name or ID.

The iNaturalist API supports radius, rectangle, and place queries directly. For polygons, Nearby Lifers loads observations in the bounding rectangle and tests their public coordinates against the polygon. Points outside the polygon do not contribute species or counts. Obscured coordinates may be imprecise, and private coordinates are unavailable. Concave polygons are supported. Crossing edges and polygons spanning the international date line are rejected.

Polygon searches are limited to 10,000 observations in the bounding rectangle after month and life-group filtering. Larger searches fail with instructions to narrow the query. No partial list is presented as complete. Requests are spaced below 100 per minute, paginated, and canceled when a newer search replaces them. No API key is needed. The implementation uses the [iNaturalist v1 API](https://api.inaturalist.org/v1/docs/).

## Printing

Choose a photo grid or a compact taxon checklist, then open Print options. The preview and printout contain the same visible species. Letter measures 8.5 by 11 inches. Half Letter measures 5.5 by 8.5 inches. A5 measures 148 by 210 mm, and A6 measures 105 by 148 mm. Photo grids default to 3 columns and a maximum of 4 rows on every paper size. Set Columns per page and Rows per page (maximum) to choose from 1 to 8 in either direction. The row setting is a limit. Complete rows are balanced across the fewest pages, so the final page is not left with a single leftover row when a more even distribution is possible. Every page spreads its rows over the full available height. Font size (pt) sits alongside those controls and defaults to 10. It accepts whole sizes from 6 to 24 points. Group labels, common names, scientific names, record counts, and optional photo credits all use that size. Common names stay bold and scientific names stay italic. Changing the font preserves the chosen column count and row limit. Larger labels use more of each card, and the photo frame becomes shorter to keep the text at its selected size. Earlier links without dimensions or a font size use these defaults. Checklist density still controls its text and column count.

Photo grids are borderless galleries with 2.5 mm of white space between columns and 3 mm between rows. Each photo fills its card width and expands vertically to use the space left by the group label and text. The colored group bar touches its top edge, with common and scientific names immediately below the image and records on their own line. Photo cards have no checkboxes. Printed taxon checklists retain theirs. Photos use a centered crop from the larger available image. Their aspect ratio changes to fit the page. The [iNaturalist image size documentation](https://github.com/inaturalist/inaturalist-open-data#readme) lists a square thumbnail, but it is only 75 by 75 pixels. The print layout measures the labels at the chosen font size, aligns group bars and text areas within each row, and gives all remaining height to the photos. The rows account for the white gutters and fill the page down to the footer. A partial final row keeps unused cells empty. Text is never shrunk to make room for a photo. Photos are never stretched. If a photo is unavailable, its frame stays blank. Group labels use the nine-color [ColorBrewer Pastel1 palette](https://d3js.org/d3-scale-chromatic/categorical#schemePastel1). A group keeps its color across pages, and the palette repeats for later groups. Only the group bars receive these colors. Photo credits are hidden by default and can be restored with Show photo credits. Each page contains up to the chosen row limit. Groups continue through the gallery without forced page breaks. If the chosen rows, columns, and text size leave too little room for photos, the preview asks for fewer rows or columns, a smaller font, or larger paper before enabling Print or save PDF. Checklists use the selected taxonomy grouping and sort order, repeat group headings across columns, and paginate using measured row and heading heights. Individual sheets include the search context, date, and page numbers. Booklet body pages omit the header. Their footer shows the editable booklet title on the left and only the current page number on the right. The grid font setting applies to card text. Supporting booklet text remains 7.5 pt for filters, 6 pt for footers, and 9 pt for contents, or 7.5 pt for contents in Compact and Extra compact layouts. Print or save PDF through the browser dialog. Match the selected paper size, use 100 percent scale, and disable browser headers and footers. In Individual sheets mode, Half Letter is one 5.5 by 8.5 inch sheet per page. Mobile print dialogs vary in their paper-size support.

Choose Folded booklet to print on landscape Letter paper and fold to a 5.5 by 8.5 inch booklet. Print settings show the physical sheet count, including covers, contents, and padding. A visible warning appears when this count exceeds the editable sheet limit, which defaults to 40. The warning does not block printing. The limit counts double-sided sheets, each of which contains four booklet pages. Grid dimensions, font size, the photo-credit setting, and the sheet limit are stored in the search URL. Booklet pages have a 14 mm margin at the spine and 9 mm at the outside edge. The extra 5 mm of spine clearance switches sides on facing pages, including in the printed checklist and contents measurements. The cover includes the selected users with @ handles, an editable title, Nearby Lifers branding, and the generation date. The inside cover is headed Booklet search filters and prints the searched map boundary and imagery, usernames, location details, months, life groups, life-list quality rules, nearby filters, observed-species setting, grouping, sort order, format, and density. Beside the map, a 44 mm QR code and a clickable link restore the exact search on the public website, including every polygon vertex and the print settings. This QR is separate from the website QR on the back cover. Exceptionally long polygon URLs can exceed QR capacity. In that case, the booklet keeps the exact clickable PDF link and explains why a QR could not be generated. Place geometry is retained with the completed search. If imagery cannot load, the outline still prints with an explanatory caption.

Grouped booklets put the contents next, starting on page three. Contents entries point to the first printed page of each group and update when the rows, columns, text size, format, or filters change. Long contents paginate. Compact and Extra compact use two contents columns. Choose Group by None to omit the contents. The back cover has a small QR code and credit linking to the public Nearby Lifers website, even when printed from a local preview. Blank pages are added before the back cover as needed to reach a multiple of four. The preview labels each sheet front and back. Blank-page labels appear only in the preview.

The output is already arranged in folding order, with two booklet pages per printed side. Print double-sided with short-edge flipping at 100 percent scale. Disable browser headers and footers, and leave the printer's own booklet or multiple-pages-per-sheet modes off. The browser cannot set the printer's duplex controls. Stack the sheets in order and fold along the spine. Three half-inch staple guides print on every side. Their centers are 1.5 inches from the top, 4.25 inches from the top, and 1.5 inches from the bottom. Each dashed guide has an endpoint mark for each hole. The design assumes a half-inch staple crown. Use the endpoint marks to pierce the stacked sheets and insert staples manually. Print at 100 percent for the spacing to stay accurate.

## Development

Use Node 22.18 or later. Install dependencies and start the development server with the following commands.

```sh
npm install
npm run dev
```

Run the checks with the following commands. The browser suite uses deterministic API fixtures and checks URL restoration, username search, history, quality filters, taxonomy grouping, sorting, polygon controls, mobile layout, all paper and density combinations, and booklet covers, map boundaries, contents pagination and references, physical staple placement, QR decoding, balanced photo-gallery pagination, cropped frames that fill every page height, aligned photo edges and flush group bars, uniform numeric font sizes, exact-search QR decoding, mirrored spine margins, invalid-grid handling, group-color consistency, credit visibility, physical sheet warnings, page order, and PDF dimensions.

```sh
npm test
npm run lint
npm run build
npx playwright install chromium
npm run test:browser
```

GitHub Pages builds use `GITHUB_PAGES=true npm run build`. Deployment remains a separate step.
