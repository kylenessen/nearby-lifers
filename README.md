# Nearby Lifers

Nearby Lifers is a responsive website for finding iNaturalist species that you have not observed yet. Run a search, copy its link, or bookmark it. Opening that link restores its settings and reuses a completed search saved on this device. Results stay until you choose Refresh results. There is no installation step or saved login state. An optional offline download saves the website and photos too.

## Searching and sharing

Use the Username field to search iNaturalist by login or display name. Choose a match with the pointer or arrow keys and Enter, or enter an exact username directly. Links containing multiple comma-separated usernames still work. Their worldwide species lists are combined, and an observation from any listed user makes that species already observed. The life list always includes Research Grade and Needs ID. Casual observations also count by default. Select “Exclude users’ casual observations” to leave them out. All dates and locations count toward the life list. Identifications above species rank cannot establish that a particular species has been observed. Subspecies observations count toward their parent species.

Nearby results use the selected location, months, and life groups. Months apply across all years. The initial search uses the previous, current, and next month. Once a URL is created, those months are explicit and stay fixed when that bookmark is reopened. Nearby casual-only and expected-range filters are separate from the users’ life-list quality setting. “Include already observed species” adds those species to the display and marks them as seen.

The address changes when you run a search. Display filters and print settings update it immediately. Unsaved search edits are labeled, and sharing and printing are disabled until the new search runs. Browser Back and Forward restore previous searches. Each bookmark can be added to a phone’s home screen using the browser’s normal website shortcut feature. Mobile bookmarks open with the search controls collapsed so results are visible immediately. Use Edit search to change them.

All settings live in query parameters. These include `source`, `users`, `area`, coordinates or `place`, `radius`, `months`, `groups`, `user_casual`, `hide_casual`, `hide_unexpected`, `show_observed`, `layout`, `paper`, `density`, `columns`, `rows`, `font_size`, `sort`, `grouping`, `print`, `title`, `credits`, and `sheet_limit`. `v=1` identifies the URL format. New display options have defaults, so earlier links continue to work. Polygon vertices use latitude and longitude pairs in `polygon`. Links preserve a deployment subdirectory such as `/nearby-lifers/`. Invalid locations or unsupported URL versions show an error instead of running a different search.

The checklist uses iNaturalist taxonomic ancestry to group species. Taxonomic groups use families such as ducks and geese or herons, with Passeriformes grouped together as perching birds. You can instead group everything by family or order. Missing ancestry falls back to the life group. Sort by common name, scientific name, or reported observation count within groups. Set Group by to None for a single globally sorted list. Photo grids use the same grouping and sort controls. Groups flow through the grid without empty rows or forced page breaks. The default is most frequently recorded first within each group, using the selected area and months. Large, Comfortable, Compact, and Extra compact densities affect screen layouts and printed checklist spacing. For printed photo grids, text size and grid dimensions can be adjusted separately.

## Optional GBIF records

Nearby record sources offers iNaturalist alone, iNaturalist plus eBird via GBIF, and iNaturalist plus all GBIF datasets including eBird. The URL stores this choice as `source=inaturalist`, `source=ebird`, or `source=gbif`. Older bookmarks default to iNaturalist. Changing the source requires running the search. The selected source is printed in Search Filters.

GBIF supplies nearby species through paginated species-count facets, without exporting individual occurrences. Queries use the selected months across all years, coordinates, present occurrences, and GBIF's geospatial quality checks. Records without a species-level classification are excluded with a visible count. eBird mode restricts the query to the [eBird Observation Dataset](https://www.gbif.org/dataset/4fa7b334-ce0d-4e88-aaae-2e0c138d049e). [Cornell documents an annual update schedule](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data), so these are historical records rather than live sightings. The GBIF mode includes observations, specimens, and other eligible record types from its contributing datasets.

The worldwide life list, photos, common names, and groupings still come from iNaturalist. GBIF names must match a unique active iNaturalist species, by scientific name or an exact synonym in the same life group. Ambiguous or unmatched taxa appear in an expandable review list with GBIF links and are excluded from the guide. GBIF never replaces the user's Research Grade, Needs ID, or optional Casual life-list records. Nearby casual-only and expected-range filters apply only to the iNaturalist contribution. Species with GBIF records remain eligible, as those records do not have iNaturalist quality or expected-range labels.

Counts remain separate by source. For each matched species, the display and frequency sort use the larger source count. The two totals are never added, because GBIF includes copies of iNaturalist data. Disjoint GBIF species buckets that map to one iNaturalist species are combined within GBIF. Source details expose both totals. This is a conservative comparison, not a count of unique sightings across all datasets. GBIF publishers can themselves contain duplicate records. Adding eBird separately to the all-GBIF mode is deliberately not offered.

Radius and rectangle queries preserve their boundaries. Drawn polygons preserve their vertices and use counterclockwise WKT with correctly oriented holes. Detailed iNaturalist place outlines may exceed GBIF's GET URL limit. Only these outlines are simplified, using the first tolerance that fits from approximately 1, 5, 10, 25, 50, 75, or 100 metres. The app and printed filters disclose this approximation. It never substitutes the bounding rectangle. Boundaries that still do not fit fail with instructions to draw a smaller area or use a radius.

Completed searches, including life lists, matched GBIF species, source warnings, and place boundaries, are saved in IndexedDB without a time limit. The collection date is shown beside Refresh results. Reopening a saved search makes no observation, GBIF, taxonomy, or place-detail requests. Refresh bypasses the saved result and the one-hour in-memory GBIF count cache, then replaces the stored result only after every source succeeds. Failed or canceled refreshes retain the previous result and its original date. Small in-memory taxonomy caches can still be reused for 24 hours. Storage failures leave the current result usable and show a message. Both APIs use request pacing, 30-second request timeouts, and up to two retries for network failures, HTTP 408, HTTP 429, and server errors. Retries back off and respect Retry-After. Cancellation interrupts requests and waits. Permanent errors and incomplete searches are not cached. A failed selected source stops the search with a visible error instead of presenting a partial guide.

## Saved results and offline use

Results save automatically on the browser and device where a search completes. They never refresh or expire on a timer. Use Refresh results to fetch the latest life list and nearby data. Device storage offers Remove saved copy and Clear all saved searches. Removing a copy leaves the current screen open but makes the next visit rebuild it. The canonical search key includes the area, users, months, life groups, source, and life-list quality preference. Layout and print changes reuse the same result. The URL remains the source of all search and print settings. Sharing a link shares those settings, not another device's stored results.

While connected, choose Save for offline and keep the page open until it confirms completion. This explicitly registers a service worker scoped to the website directory. It saves the built HTML, JavaScript, styles, and icons, then downloads every available species photo in the completed search. Hidden and already observed species are included so display filters can still change offline. Photos are downloaded four at a time, checked by decoding, and retried up to twice after failures with a 20-second timeout per attempt. Photos from hosts without cross-origin read access are saved as opaque responses and decoded through the service worker before they count as complete. Browsers may charge more storage for these responses. Storage exhaustion stops the download with a clear message. Failed or canceled downloads stay incomplete. Retrying downloads only missing photos. The app verifies website files and photos are present before showing Ready for offline use. After refreshing, save offline again for any new photos. Removing saved results also removes their downloaded photos. Website files remain available to open other saved searches.

Saved searches can reopen in a new tab without network access, including their photos, grouping, sorting, and print layouts. Satellite map tiles are not downloaded. Search boundaries remain visible and printable with an offline caption. New searches, refreshed records, user and place lookup, and external links need internet access. There is no web app manifest, install prompt, or forced standalone window. Existing offline registrations check for website updates when opened online. They do not refresh search data.

Offline saving asks the browser for persistent storage when supported. The storage panel reports whether it was granted. A website cannot promise permanent storage on every phone. Browsers can remove unprotected data, users can clear site storage, and private browsing data normally disappears when the session ends. Keep a PDF as well if you need a copy independent of browser storage. See the [browser storage documentation](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria). Offline support requires HTTPS or localhost. Development mode does not register a service worker. Use the production preview to test it.

## Map selection

Explore mode lets you move the map without changing the selected area. Radius mode sets a center with one tap. Rectangle mode uses two opposite corners and previews the boundary. Polygon mode lets you tap corners, undo points, drag numbered corners, and finish the shape. Existing polygons can be edited. Escape cancels drawing. With the map focused, arrow keys pan and Enter adds a point at the center. Place search accepts an iNaturalist place name or ID.

The iNaturalist API supports radius, rectangle, and place queries directly. For polygons, Nearby Lifers loads observations in the bounding rectangle and tests their public coordinates against the polygon. Points outside the polygon do not contribute species or counts. Obscured coordinates may be imprecise, and private coordinates are unavailable. Concave polygons are supported. Crossing edges and polygons spanning the international date line are rejected.

Polygon searches are limited to 10,000 observations in the bounding rectangle after month and life-group filtering. Larger searches fail with instructions to narrow the query. No partial list is presented as complete. Requests are spaced below 100 per minute, paginated, and canceled when a newer search replaces them. No API key is needed. The implementation uses the [iNaturalist v1 API](https://api.inaturalist.org/v1/docs/).

## Printing

Choose a photo grid or a compact taxon checklist, then open Print options. The preview and printout contain the same visible species. Letter measures 8.5 by 11 inches. Half Letter measures 5.5 by 8.5 inches. A5 measures 148 by 210 mm, and A6 measures 105 by 148 mm. Photo grids default to 3 columns and a maximum of 4 rows on every paper size. Set Columns per page and Rows per page (maximum) to choose from 1 to 8 in either direction. Every page uses the same full grid. The final page leaves unused cells empty, including whole rows, so its photos stay the same size as those on a full page. Font size (pt) sits alongside those controls and defaults to 9. It accepts whole sizes from 6 to 24 points. Common names, scientific names, record counts, and optional photo credits all use that size. Common names stay bold and scientific names stay italic. Changing the font preserves the chosen column count and row limit. Larger labels use more of each card, and the photo frame becomes shorter to keep the text at its selected size. Earlier links without dimensions or a font size use these defaults. Checklist density still controls its text and column count.

Photo grids are borderless galleries with 2.5 mm of white space between columns and 3 mm between rows. Each photo fills its card width and expands vertically to use the space left by the names and optional credits. Group names appear once in a compact page header. It shows the first group through the last group on that page, or a single group name when all species belong to it. The header uses 9 pt text, matching the booklet footer. Longer group ranges wrap, with the same reserved header height on every page so photo proportions stay consistent. Ungrouped guides omit it. Common and scientific names sit below the image. Records sit at its bottom right on a small opaque white badge with square corners. Photo cards have no checkboxes. Printed taxon checklists retain theirs. Photos use a centered crop from the larger available image. Their aspect ratio changes to fit the page. The [iNaturalist image size documentation](https://github.com/inaturalist/inaturalist-open-data#readme) lists a square thumbnail, but it is only 75 by 75 pixels. The print layout measures the largest information block at the chosen font size, reserves that space on every card, and gives the remaining row height to the photos. Every photo uses the same frame proportions throughout the guide. The rows account for the white gutters and fill the page down to the footer. A partial final row keeps unused cells empty. Text is never shrunk to make room for a photo. Photos are never stretched. If a photo is unavailable, its frame stays blank. Photo credits are hidden by default and can be restored with Show photo credits. Each page contains up to the chosen row limit. Groups continue through the gallery without forced page breaks. If the chosen rows, columns, and text size leave too little room for photos, the preview asks for fewer rows or columns, a smaller font, or larger paper before enabling Print or save PDF. Checklists use the selected taxonomy grouping and sort order, repeat group headings across columns, and paginate using measured row and heading heights. Individual sheets and booklet body pages use the same compact formatting. Photo pages retain only the group range in their header. Their 9 pt footer shows the editable guide title on the left and only the current page number on the right. Individual sheets use 9 mm margins on all sides. Guide title shares the URL title setting with the booklet cover. The grid font setting applies to card text. Booklet filters and footers use 9 pt in every density. Contents use 12 pt. Search Filters is a single page. Print or save PDF through the browser dialog. Match the selected paper size, use 100 percent scale, and disable browser headers and footers. In Individual sheets mode, Half Letter is one 5.5 by 8.5 inch sheet per page. Mobile print dialogs vary in their paper-size support.

Choose Folded booklet to print on landscape Letter paper and fold to a 5.5 by 8.5 inch booklet. Print settings show the physical sheet count, including covers, contents, and padding. A visible warning appears when this count exceeds the editable sheet limit, which defaults to 40. The warning does not block printing. The limit counts double-sided sheets, each of which contains four booklet pages. Grid dimensions, font size, the photo-credit setting, and the sheet limit are stored in the search URL. Booklet pages have a 14 mm margin at the spine and 9 mm at the outside edge. The extra 5 mm of spine clearance switches sides on facing pages, including in the printed checklist and contents measurements. The cover places the selected @ handles on a separate line above “Nearby Lifers for:” and the editable title. The username and tool name use the same 22 pt Georgia font. It shows a full month date without a Generated prefix. Location details appear in the filter section. The inside cover is headed Search Filters and prints the searched map boundary and imagery, usernames, location details, months, life groups, life-list quality rules, nearby filters, observed-species setting, grouping, sort order, format, and density. A Generated on row repeats the cover date. When a saved search was collected on a different day, a Results collected row also prints that date. Printing instructions below the table specify Letter paper, landscape orientation, double-sided printing with short-edge flipping, 100 percent scale, and folding and stapling. The filter page has no QR code or search link. The website QR remains on the back cover. Place geometry is retained with the completed search. If imagery cannot load, the outline still prints with an explanatory caption.

Grouped booklets put the contents after the filter page, starting on page three. Contents entries point to the first printed page of each group and update when the rows, columns, text size, format, or filters change. Long contents paginate. Compact and Extra compact use two contents columns. Choose Group by None to omit the contents. The back cover has a small QR code and credit linking to the public Nearby Lifers website, even when printed from a local preview. Blank pages are added before the back cover as needed to reach a multiple of four. The preview labels each sheet front and back. Blank-page labels appear only in the preview.

The output is already arranged in folding order, with two booklet pages per printed side. Print double-sided with short-edge flipping at 100 percent scale. Disable browser headers and footers, and leave the printer's own booklet or multiple-pages-per-sheet modes off. The browser cannot set the printer's duplex controls. Stack the sheets in order and fold along the spine. Three half-inch staple guides print on every side. Their centers are 1.5 inches from the top, 4.25 inches from the top, and 1.5 inches from the bottom. Each dashed guide has a small round dot at each endpoint to mark the punch holes. The distance between dot centers is half an inch. The design assumes a half-inch staple crown. Use the endpoint marks to pierce the stacked sheets and insert staples manually. Print at 100 percent for the spacing to stay accurate.

## Development

Use Node 22.18 or later. Install dependencies and start the development server with the following commands.

```sh
npm install
npm run dev
```

Run the checks with the following commands. The browser suite uses deterministic API fixtures and checks URL restoration, username search, history, quality filters, taxonomy grouping, sorting, polygon controls, mobile layout, all paper and density combinations, and booklet covers, map boundaries, contents pagination and references, physical staple placement, QR decoding, fixed photo-gallery pagination, identical cropped frames on full and partial pages, aligned photo edges, page group ranges and wrapping headers, opaque record badges, uniform numeric font sizes, single-page search filters with printing instructions, mirrored spine margins, invalid-grid handling, matching cover typography, credit visibility, physical sheet warnings, page order, and PDF dimensions. GBIF checks cover source restoration, retries, caching, taxonomy ambiguity, life-list preservation, source count overlap, spatial boundaries, partial failures, and printed source settings.

```sh
npm test
npm run lint
npm run build
npx playwright install chromium webkit
npm run test:browser
npm run test:offline
```

GitHub Pages builds use `GITHUB_PAGES=true npm run build`. The offline suite builds with the GitHub Pages base path and tests real service workers in Chromium and WebKit. It checks fresh offline tabs, cached photos, print layouts, retrying failed image downloads, validating photos without CORS headers, storage exhaustion, shell repair, and storage cleanup. Deployment runs when main is pushed.
